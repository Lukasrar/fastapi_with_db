# FastAPI with Database

A small REST API for managing user accounts and personal to-do items. It is
built with FastAPI, SQLAlchemy, and a local SQLite database. Authentication
uses OAuth2 password-form login and bearer tokens.

## Features

- Create accounts and authenticate with a username and password.
- Store passwords as bcrypt hashes.
- Issue JWT access tokens that expire after 20 minutes.
- Create, list, retrieve, update, and delete the authenticated user's to-do
  items.
- Generate interactive API documentation with FastAPI.

## Technologies

- **Python** — programming language.
- **FastAPI** — REST API framework and request handling.
- **SQLAlchemy** — ORM and database sessions.
- **SQLite** — local relational database.
- **Pydantic** — request and response data validation.
- **OAuth2 password flow** — accepts username and password for login and uses
  bearer tokens for protected endpoints.
- **JSON Web Tokens (JWT)** — access-token format, implemented with
  `python-jose`.
- **Passlib and bcrypt** — password hashing and verification.
- **Uvicorn** — ASGI server used to run the application.
- **OpenAPI, Swagger UI, and ReDoc** — API schema and interactive
  documentation generated by FastAPI.

## Requirements

- Python 3.9 or newer.
- `pip`.

## Installation

Clone the repository, change into its directory, create a virtual environment,
and install the dependencies:

```bash
git clone https://github.com/Lukasrar/fastapi_with_db.git
cd fastapi_with_db
python3 -m venv .venv
source .venv/bin/activate
python -m pip install --upgrade pip
python -m pip install -r requirements.txt
```

On Windows PowerShell, activate the environment with:

```powershell
.venv\Scripts\Activate.ps1
```

## Run the application

Start the development server from the repository root:

```bash
uvicorn main:app --reload
```

The API is available at <http://127.0.0.1:8000>.

| Resource | URL |
| --- | --- |
| Interactive Swagger UI | <http://127.0.0.1:8000/docs> |
| ReDoc | <http://127.0.0.1:8000/redoc> |
| OpenAPI schema | <http://127.0.0.1:8000/openapi.json> |

The application creates the SQLite tables at startup. The database URL is
currently fixed in `database.py` as `sqlite:///./todosapp.db`, so the database
file is stored in the current working directory.

## Authentication

### Register a user

Send a JSON request to `POST /auth/`:

```bash
curl -X POST http://127.0.0.1:8000/auth/ \
  -H "Content-Type: application/json" \
  -d '{
    "username": "alice",
    "email": "alice@example.com",
    "first_name": "Alice",
    "last_name": "Example",
    "password": "change-this-password",
    "role": "user"
  }'
```

The request body requires `username`, `email`, `first_name`, `last_name`,
`password`, and `role`.

### Log in

Send the username and password as form fields to `POST /auth/token`:

```bash
curl -X POST http://127.0.0.1:8000/auth/token \
  -H "Content-Type: application/x-www-form-urlencoded" \
  -d "username=alice&password=change-this-password"
```

The response contains an `access_token` and `token_type` (`bearer`). Include
the token in the `Authorization` header for protected endpoints:

```bash
curl http://127.0.0.1:8000/ \
  -H "Authorization: Bearer <access-token>"
```

## API endpoints

All to-do endpoints require a valid bearer token. A to-do item belongs to the
authenticated user; retrieving, updating, or deleting another user's item
returns `404`.

| Method | Path | Description |
| --- | --- | --- |
| `POST` | `/auth/` | Register a user |
| `POST` | `/auth/token` | Authenticate and obtain a bearer token |
| `GET` | `/` | List the authenticated user's to-do items |
| `GET` | `/todo/{todo_id}` | Get one of the authenticated user's items |
| `POST` | `/todo` | Create a to-do item |
| `PUT` | `/todo/{todo_id}` | Replace an existing item |
| `DELETE` | `/todo/{todo_id}` | Delete an item |

The to-do request body has this shape:

```json
{
  "title": "Read the documentation",
  "description": "Review the API endpoints",
  "priority": 2,
  "complete": false
}
```

Validation requires a title of at least 3 characters, a description between 3
and 100 characters, and a priority from 1 through 6. The `complete` field is a
boolean.

An admin router is present in `routers/admin.py`, but it is not included by
`main.py`; its routes are therefore not currently available in the running
application.

## Project layout

```text
.
├── main.py           # FastAPI application and router registration
├── database.py       # SQLite URL, SQLAlchemy engine, and session factory
├── models.py         # User and to-do database models
├── requirements.txt  # Python runtime dependencies
└── routers/
    ├── auth.py       # Registration, login, and token validation
    ├── todos.py      # Authenticated to-do operations
    └── admin.py      # Admin router (not currently registered)
```

## Development notes

- There is no test suite or migration setup in the repository.
- Tables are created with SQLAlchemy `create_all` when the application starts;
  this does not migrate existing tables when models change.
- This project is intended as a learning example, not for production use. The
  JWT signing key is hard-coded, and account registration accepts a role in
  its request body. Both need to be redesigned before deployment.
